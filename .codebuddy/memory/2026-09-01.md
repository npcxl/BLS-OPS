## 阶段：P3 服务 / 日志 / 容器 / 网关 / 项目部署

新增后端 `safe.rs`（安全边界）、`remote.rs`（共享 exec 助手）、`systemd.rs`、`journal.rs`、`docker.rs`、`nginx.rs`；db 升到 v3（projects / deployments）；前端新增 5 个视图 + `useCommandSession` + `module-frame.tsx`。

**安全执行层 `safe.rs`（最重要的设计）**：
- `Capability` **枚举**是唯一把「动作」翻译成命令字符串的地方，一个穷举 `match` 就是完整审计面。新增动作必须来这里加变体。
- 三类校验：字符集白名单（`is_safe_char`，不含引号/反斜杠/`$`/反引号/空白/`;&|<>`）、类型专属规则（systemd 单元必须以已知后缀结尾、容器名不能以 `-` 开头、路径必须绝对且无 `..` 段）、范围校验（行数 1–10000、优先级 0–7）。
- 一切插值都 `shell_quote()` 单引号包裹，位置参数前加 `--`（`systemctl restart -- 'nginx.service'`）。
- 部署步骤：命令白名单（git/npm/docker/systemctl/…）+ 禁止 shell 操作符 + 绝对路径必须在 `deploy_path` 内 + `rm` 禁用 `..`。
- **校验必须发生在任何网络 I/O 之前**：`remote::run_on_linux()` 先 `capability.command()?` 再 `require_linux()`。e2e 因此能断言「恶意参数被拒时服务端命令日志一条都没增加」。（这是 e2e 跑出来才发现的真 bug：原先先跑 `uname` 再校验。）

**`tests/p3_e2e.rs`（25 个）的关键手法**：测试服务端把收到的每条命令记进 `Log`，测试从外部断言命令字符串。这比单测更有力——它证明的是「真正发出去的东西」，且能证明被拒绝的参数压根没出门。

**各模块要点**：
- systemd：`list-units` + `list-unit-files` 并发读后合并；`enabled: Option<bool>`（`static`/`indirect`/`masked` 是 `None`，绝不假装 false）；排序 failed→running→其他。
- journal：`journalctl -o json`；MESSAGE 可能是字节数组（非 UTF-8）；优先级缺失按 6（info）；`-p` 在服务端过滤。
- docker：Go 模板用 `|` 分隔（容器名/标签/端口映射都含空格）；`--` 表示无采样，按 0 处理；缺 docker 时 `unavailable_reason` 而非空列表；`docker rm` 必须 `-f`。
- nginx：两套布局（Debian `sites-available`+`sites-enabled`软链；RHEL `conf.d` 天然生效）；同名站点 `conf.d` 优先；**`nginx -t` 的判定写在 stderr**（`test_config` 用 `manager.exec` 直接拿双流）；保存 → 校验 → 通过才重载。
- 部署实时日志：**前端先生成 deployment id 并订阅 `deploy-progress-<id>`，再发起执行**，`deployment_execute` 接受可选 `deploymentId`。否则早期输出会丢。

**前端**：
- `useCommandSession(tab)` 统一管连接/HostKey 挑战/`ssh-closed` 监听/卸载清理，5 个模块共用。
- `module-frame.tsx` 提供 `ModuleFrame`（状态条 + 连接横幅 + 服务器选择器）、`RefreshButton`、`ModuleEmpty`。

### russh 0.63 API 知识（本会话实测确认）
- `Handle::is_closed()`：连接任务一结束（远端断开/transport 错误/keepalive 超时）即 true，是「transport 是否死亡」的可靠信号。
- `client::Handler::disconnected(reason)`：收到远端 Disconnect 或 transport 错误时触发；`DisconnectReason::{ReceivedDisconnect, Error}`。
- `channel_open_session` 错误语义：`SendError`/`Disconnect`/`HUP` = transport 死；`ChannelOpenFailure(..)` = 服务器拒绝该通道但连接仍活。
- 服务端 `Session::disconnect(Disconnect::ByApplication, desc, lang)` 可在 exec_request 里主动断开当前连接（测试 kill_switch 的实现）。
- `RunningServerHandle::shutdown` 会向每个已建立连接发送 SSH Disconnect —— e2e 模拟「服务端主动关闭」的标准手段。
