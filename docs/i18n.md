# BLS-OPS 国际化（i18n）规范

技术栈：`i18next` + `react-i18next`（v26/v17）。**natural keys**：key 就是英文文案本身。

## 核心事实

- 默认语言 **英文**（`en` 不需要翻译资源 —— 找不到 key 时原样返回 key，界面即英文）。
- `zh-CN` 必须全量；其余语言（zh-TW/ja/ko/es/fr/de/ru/pt-BR）尽力覆盖，缺失回退英文。
- 切换语言：`changeLocale(code)` → localStorage 持久化 → `i18next.changeLanguage` → **所有 `useTranslation()` 组件自动重渲染**（动态刷新，无需重启）。
- 每个语言一个目录 `src/i18n/locales/<code>/`，目录内**按模块分文件**（common / workbench / terminal / servers / commandCenter / files / projects / monitor / docker / nginx / settings / errors），`index.ts` 只做合并。

## 怎么用

```tsx
// React 组件（响应式：语言切换即重渲染）
import { useTranslation } from "react-i18next";
const { t } = useTranslation();
t("Connect")
t("Connected to {{host}}", { host })            // 插值
t("{{count}} servers", { count: 3 })            // 计数
```

```ts
// 纯 TS 模块（错误消息工厂、store 提示语等，无 hook 可用）
import { i18n } from "@/i18n";
i18n.t("Session not found");
```

## 哪些文案要抽取

**要**：JSX 可见文本、`title` / `aria-label` / `placeholder`、ConfirmDialog 的 title/description、会显示到 UI 的 `Error` message、`window.confirm` 消息、下拉选项 label、空态文案、按钮文字。

**不要**：代码注释（保持中文）、`console.*` 日志、测试名称（describe/it）、发给 xterm 的终端内容（`terminal.write`）、正则里匹配中文输出的模式、变量名。

## 语言文件写入规则

1. key 必须与 `t("...")` **逐字一致**（含标点与 `{{占位符}}`）。
2. 跨模块通用词（Confirm/Cancel/Save/Delete/Loading…）放 `common.ts`，已有就直接复用。
3. 模块文案放对应模块文件（如 terminal 的都进 `terminal.ts`），`index.ts` 不要动。
4. 格式：

```ts
export default {
  Connect: "连接",
  "Connected to {{host}}": "已连接 {{host}}",
} as const;
```

## 测试怎么办

测试跑在默认语言（en）下，断言里的中文要换成对应的**英文文案**（即 key 本身）。推荐直接写 key 字符串（如 `toContain("Confirm")`），不要在测试里调 `i18n.t()`（keep it simple）。

## 红线

- 不重构无关代码、不改格式化风格、不动 Rust 文件。
- 模块级常量（对象/数组）里不能用 hook → 存英文 key，渲染处统一 `t(...)`。
- 插值只允许 `{{name}}` 占位；**禁止字符串拼接文案**（`"已连接 " + host` 必须改成插值）。
- 中文注释里的 i18n 说明保持中文（项目惯例）。
