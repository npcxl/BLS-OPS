# 2026-09-01

## 阶段：服务器状态监控（只读 Linux）

新增 `src-tauri/src/monitor.rs` + `src-tauri/tests/monitor_e2e.rs` + 前端 `ServerMonitorView` / `monitor-store`。

后端要点：
- `SshSession::exec(command, timeout)`：独立 exec 通道，读完 exit-status+eof 即 `channel.close()`；`timed()` 用 `tokio::select!` 在「deadline / 会话关闭 watch 信号 / 完成」之间竞争，`sftp.rs` 等既有逻辑未动。
- `SshSession.writer` 改为 `Mutex<Option<SessionWriter>>`，新增 `SshSessionManager::connect_command()`（0×0 → 不请求 PTY、不打开 shell）；监控 session 的 `ssh_input` 会明确报「没有交互式终端」。
- `SshSession.closed: watch::Sender<bool>`，`shutdown()` 里 `send(true)` → 取消该会话所有在途命令。
- 命令表是 `monitor.rs` 里的常量，Tauri 命令只收 `sessionId`。
- CPU/网速是两次采样的差值；首次采集会隔 200ms 再读一次 `/proc/stat` 与 `/proc/net/dev`，从不填 0 占位。
- `resolve_rates(cpu: Option, net: Option)`：只采 CPU 时不清空网络基线（否则会算成「开机以来的平均值」）。
- `MonitorRegistry`（AppState.monitor）存速率基线；`ssh_disconnect` 里 `monitor.forget(sessionId)`。

前端要点：
- 新 tab 类型 `monitor`，入口：服务器右键「打开监控」+ 命令面板。`ssh_connect_monitor` 开无 PTY 会话。
- 轮询条件：phase∈{connected,error} && 未暂停 && 该 Tab 是当前活动页签 && `document` 可见。
- 历史窗口 30 分钟（360 点上限）。

验证：`pnpm test` 23、`pnpm build`、`cargo fmt --check`、`cargo check --all-targets`、`cargo test --all-targets`（60 单测 + 12 监控 e2e + 27 SSH e2e）、`cargo build` 全绿；本机拉起 `ops-workbench.exe` 窗口标题 `BLS-OPS`。
