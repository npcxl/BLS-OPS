### #5 终端输出合并（本轮）
- **放在前端**，不碰 Rust 的 `reader.wait()`：在 `select!` 里取消 `wait()` 有丢消息风险。
- `use-terminal-session.ts`：把原来的 listener 回调体抽成 `handleOutput(output)`，
  listener 只做 `pendingOutput += payload` + `setTimeout(0)` 调度。
- 三条保证：顺序（按到达 append）、上限（≈512 KiB 立即 flush）、不拖回显
  （用 `setTimeout(0)` 而非 rAF —— 窗口最小化时 rAF 会暂停）。

- **天然背压**：前端处理慢 → Rust `reader.wait()` 阻塞 → SSH channel window 不满 →
  远端暂停发送。所以没有额外实现"消费进度回传"。

## 第六轮：#1 剩余两项 + #4

### #1 `du` 可取消
`compute_du` 的 `manager.exec(...)` 包进 `tokio::select!`，与 `wait_cancel(cancel)` 竞争。
取消时放弃等待 → exec future 被 drop → channel 关闭（远端通常收到 SIGHUP），
**扫描名额立即释放**。注释写明：没有信号通道能保证远端进程立刻退出。

### #1 轻量遍历接口
新增 `SshSessionManager::sftp_walk_dir` + `WalkEntry { name, kind, size }`：
- 不 `canonicalize`、不建 `RemoteFileEntry`（permissions/modified/hidden）、**不排序**；
- **不对缺失 size 的目录做 lstat**（目录大小对求和没用）；
- 只对缺失 size 的**普通文件**按 8 个一批补查。
`dirsize::walk` 改用它（之前走 `sftp_list_dir`，每层都做上述全部工作）。

### #4 本地补全不再等远程防抖
`CompletionScheduler.request(ctx, { immediate })`：immediate 时 `setTimeout(0)`（合并同一轮输入）。
`use-terminal-completion` 判断"光标前只有一个词"→ 命令名补全 → immediate；
带参数的仍走 150–250ms 防抖（可能查远程目录/Docker）。
测试：`scheduler.test.ts` 新增"immediate 用 0，远程用 debounceMs"。

## 第五轮：远程保存的权限保留

**API（已查 crate 源码，不是猜的）**：`russh-sftp 2.4.0`
- `SftpSession::set_metadata(path, Metadata)` 存在；`Metadata` 就是
  `russh_sftp::protocol::FileAttributes`（`src/client/fs/mod.rs:13` 的 `pub type`）。
- `FileAttributes` 有 `permissions: Option<u32>` 且 derive 了 `Default`，
  所以可以只构造权限字段：`FileAttributes { permissions: Some(p), ..Default::default() }`。

**实现**（`atomic_write`）：
1. `symlink_metadata(canonical)` 拿原属性（同时用于判断存在）；
2. 写完临时文件、校验大小之后，**rename 之前**把原 `permissions` 设到临时文件
   —— rename 保留的是临时文件的权限，不复制就会把 0600 变成 0644；
3. `set_metadata` 失败时：
   - 原权限 `& 0o077 == 0`（仅所有者可访问，如 0600/0700）→ **删除临时文件并中止保存**，
     绝不静默放宽；
   - 组/其他本来就有权限 → 继续保存（放宽风险小）。

**边界**：个别服务器不支持 `setstat`，此时严格权限的文件会保存失败并给出明确错误 ——
这是有意的取舍（可用性让位于安全）。

**仍未解决**：两次改名（原文件→.bak、临时文件→原文件）之间的目标缺失窗口。
SFTP v3 的 rename 不覆盖已存在文件，没有 `posix-rename@openssh.com` 扩展时无法消除；
最坏情况下原内容在 `.bls-bak-<uuid>` 里，不会丢。
- 两次改名之间的目标缺失窗口（SFTP v3 rename 不覆盖，无 posix-rename 时无法消除）。
