# P5.1 制品导入与多服务项目识别

配套设计文档：`docs/P5_DEPLOYMENT_CENTER_DESIGN.md`（安全模型与分层）。

## 1. 支持的输入

| 来源 | 说明 |
| --- | --- |
| 本地文件夹 | 递归只读清点；目录 / 归档 / 单文件三种来源共用同一套识别逻辑 |
| ZIP / TAR / TAR.GZ（`.zip` / `.tar` / `.tar.gz` / `.tgz`） | 读中央目录 / 顺序读条目头，**绝不解压落盘** |
| 静态 `dist` / `build` / `out` / `public` / `www` | 识别成 `StaticNginx` 候选，`artifact_kind = dist` |
| JAR（`.jar` / `.war` / `.ear`） | 按 ZIP 清点内容，识别成 `JavaJar` 候选 |
| Linux 二进制（ELF） | 只有可执行位 / `bin/` 下的无扩展名文件才会被当成候选 |
| Dockerfile | 识别成 `DockerImage` 候选，端口取自 `EXPOSE` |
| Docker Compose（`docker-compose.y*ml` / `compose.y*ml`） | **每个 service 各成一个候选**，含端口 / 依赖 / 环境变量名 |
| Docker 镜像引用 | 只登记引用（不查 registry），`basis = image_reference` |
| 服务器已有目录 | 只读列目录（BFS + 条目/深度上限），**不下载内容** |

`.tar.bz2` / `.tar.xz` 明确不支持（没编解码器）——报"不支持"，不静默失败。

## 2. 流程

```text
选择来源
  → 建任务（TaskRegistry：可取消 / 可重试 / 有进度 / 发事件）
  → fingerprint：SHA-256（流式分块，可取消）
  → source + secrets：结构清点 + 敏感内容扫描（脱敏）
  → inspect：技术栈 / 构建 / 启动 / 端口 / 健康检查 / 环境变量名 / 依赖 / 多服务候选
  → 返回识别结果（UI 展示；阻断项一票否决，"未知"绝不画成通过）
  → 用户确认（勾选要建的服务 + 选目标环境）
  → 复核指纹（对不上 = 分析失效，直接拒）
  → 事务写入：N 个 ArtifactRecord + N 个 ServiceUnit
  → 需要上传时：.part → 流式 → 校验哈希 → 同目录原子改名
```

## 3. IPC

| 命令 | 作用 |
| --- | --- |
| `deployment_artifact_import_start` | 建任务并后台开跑，立即返回任务 |
| `deployment_artifact_import_status` | 取任务（内存优先，其次库里） |
| `deployment_artifact_import_list` | 按应用列任务（内存 + 库合并） |
| `deployment_artifact_import_cancel` | 协作式取消（阶段边界生效） |
| `deployment_artifact_import_retry` | 仅失败 / 已取消可重试；远程目录来源需重新发起 |
| `deployment_artifact_import_confirm` | 落库成多服务 + 多制品（单事务） |
| `deployment_artifact_import_delete` | 删任务记录（不删制品） |
| `deployment_artifact_upload` | 上传制品并校验哈希 |

进度事件：`deployment-artifact-import-<taskId>`（前端 `artifactImportEvent(taskId)`）；
前端另有 800ms 轮询兜底，避免漏事件后卡住。

## 4. 上限（唯一来源 `deployment/artifact/limits.rs`）

| 上限 | 值 |
| --- | --- |
| 条目数 | 20 000 |
| 单文件 | 512 MiB |
| 展开总量 | 4 GiB |
| 压缩比 | 200:1 |
| 目录深度 | 24 |
| 归档内路径长度 | 1024 字符 |
| 服务候选 | 32 |
| 密钥扫描 | 400 文件 / 单文件 256 KiB / 累计 64 MiB |

超限一律**停止读取**并把 `truncated` 交给 UI，绝不假装扫完。

## 6. 下一阶段接口

- **Workflow Engine**：`PlanNode.action` + `params_json` 是唯一的动作字典；
  编译器负责把每个 `PlanActionKind` 翻成一个或多个 `safe::Capability`。
- **Releases**：`ArtifactRecord.sha256` 就是版本与内容绑定的依据；
  `ReleaseRecord.config_snapshot_json` / `nginx_backup_path` 预留给回滚。
- **健康检查**：识别结果里的 `health` 只是**建议**（HTTP 路径 / TCP 端口），
  执行与判定仍在后续阶段。
- **制品落点**：上传成功后 `source_kind` 变成 `server_existing_dir`、
  `source_ref` 指向远程绝对路径，编译器据此直接引用，不需要平行字段。
