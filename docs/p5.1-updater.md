# P5.1 桌面应用自动更新

只用 Tauri 官方 Updater（`tauri-plugin-updater` + `@tauri-apps/plugin-updater`），
第一版只提供 **stable 单通道 + GitHub Releases 静态更新源**。

## 1. 执行链路

```
启动 8s 后（仅一次 / 仅生产构建 / 可在设置里关闭）
   └─ useAutoUpdateCheck()                 src/hooks/use-updater.ts
        └─ useUpdaterStore.check()         src/stores/updater-store.ts
             └─ UpdaterClient.check()      src/lib/updater/updater-client.ts
                  └─ plugin check()  ──HTTPS──> GitHub Releases latest.json
                                              （含 version / notes / url / signature）

用户点“下载并安装”
   └─ useGuardedUpdate().requestInstall()  src/workbench/updater/use-guarded-update.ts
        ├─ 有活动 SSH / 传输 / 未保存文件 / 长任务 → UpdateRestartDialog 确认
        └─ store.install()
             ├─ client.download(onProgress)   → phase downloading + 真实进度
             └─ client.install()              → phase installing
                  └─ 插件校验 minisign 签名；失败即中止，前端无“仍然安装”入口
   └─ phase = restart_required → “立即重启” → process.relaunch()
```

状态机集中在 `useUpdaterStore`：`idle / checking / up_to_date / available /
downloading / installing / restart_required / cancelled / error`。
组件只读写 store，不直接调 `check()`。

## 2. 关键约束（勿回退）

- 签名校验常开：公钥在 `src-tauri/tauri.conf.json → plugins.updater.pubkey`，
  由 `generate_context!` 编进二进制；**没有关闭开关**，也没有“仍然安装”。
- 前端不 `fetch` 安装包、不用 shell 拉起 exe/msi，下载与安装全部由插件完成。
- CSP 未放开：更新请求由 Rust 侧发起，不需要前端 `connect-src`。
- 最小权限（`src-tauri/capabilities/default.json`）：
  `updater:allow-check` / `updater:allow-download` / `updater:allow-install` / `process:allow-restart`。
- 更新签名（minisign，验证"这个包是我们发的"）与 Windows Authenticode
  代码签名（验证"这个 exe 是谁发的"）是两件事，互不替代。当前阶段**未做**
  Authenticode，SmartScreen 仍会提示未知发布者。

## 3. GitHub Secrets 清单（只列名，不含值）

| Secret | 内容 | 来源 |
| --- | --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | Updater 私钥全文（minisign） | `pnpm tauri signer generate -w <file>` |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 该私钥的口令 | 生成时设定的口令 |

- `GITHUB_TOKEN` 由 Actions 自动提供，无需手动配置。
- 私钥与口令**只存在于 GitHub Secrets 与本机的 `.tauri/`（已被 .gitignore 忽略）**，
  仓库里只有公钥（`.tauri/updater.key.pub` 同样被忽略，公钥本体在 tauri.conf.json）。

## 4. 发布步骤

1. 决定版本（SemVer：修复 `0.1.1` / 功能 `0.2.0` / 不兼容 `1.0.0`）。
2. 同步改四处版本号：`package.json`、`src-tauri/Cargo.toml`、
   `src-tauri/tauri.conf.json`、`src-tauri/Cargo.lock`（`cargo check` 自动更新）。
3. 本地自检：`pnpm check:versions`、`pnpm build`、`pnpm test`、
   `cd src-tauri && cargo fmt --all -- --check && cargo test --all-targets`。
4. 提交并打 tag：`git tag v0.1.1 && git push origin v0.1.1`
   （或在 Actions 里手动触发，输入 `v0.1.1`）。
5. Release 工作流依次跑：版本一致性 → 前端 lint/test/build → Rust fmt/clippy/test →
   构建并签名 → 生成 `.sig` 与 `latest.json` → 上传为 **draft release**。
6. 人工检查 draft：安装包、`.sig`、`latest.json` 三者齐全，用
   `pnpm tauri signer verify` 抽查签名。
7. 点 **Publish release**：只有 published release 才会出现在
   `/releases/latest/download/latest.json`，此时线上客户端才会看到更新。

## 5. 自动检查策略

| 规则 | 实现位置 |
| --- | --- |
| 启动后延迟 8s | `AUTO_CHECK_DELAY_MS` |
| 每次启动最多一次 | `checkedThisLaunch` |
| 开发环境不检查 | `isDevRuntime()`（`import.meta.env.DEV`） |
| 失败不影响启动 | `check()` 内部吞掉异常，只写 store |
| 自动检查无更新不弹提示 | `manual=false` 时 phase 回到 `idle` |
| 自动检查发现更新 → 非阻塞卡片 | `UpdateNotification` |
| 不自动下载/安装/重启 | 只能由用户点按钮触发 |
| 重启前检查活动状态 | `update-guard.ts` + `activity-store.ts` |

## 7. 尚未支持 / 限制

- **仅 Windows x86_64 完成更新链路验证**；macOS / Linux 在
  `.github/workflows/release.yml` 中保留矩阵扩展位，但 macOS 需要 Developer ID
  签名 + 公证、Linux 需要逐发行版验证，未做之前不得宣称支持。
- 无 beta / nightly / 灰度 / 多通道，无自建更新服务器。
- 无增量补丁、无自动回滚、无强制更新。
- 无 Authenticode 代码签名（与更新签名无关）。
- 更新过程中不会主动断开 SSH：有活动状态时只会弹确认，取消即保持"等待重启"。
