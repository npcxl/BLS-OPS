# 2026-10-26 性能优化（文件大小 / 终端输入 / 编辑器搜索）

## 已确认的根因（读代码确认，非猜测）
1. **目录大小**：`RemoteFilePanel` 每次列目录为**全部**子文件夹 `computeDirSize`，无上限；
   前端队列只节流 IPC（2 并发），后端每会话 2 并发 → 浏览几个目录就积压大量任务。
2. **du 超时重扫**：`compute_du` 任何 `exec` 失败都 `DuRun::Unavailable` → 回退 SFTP，
   且 `compute_sftp` 用**新的** timeout，等于超时后重新获得完整预算。
3. **终端输入**：`RemoteFilePanel` 是 `TerminalView` 子组件但**没有 memo**，
   `onClose` 是内联箭头函数 → 终端每键重渲染都会重跑面板渲染（含 entries 遍历）。
4. **编辑器搜索**：`keyup`/`mouseup` 都调 `matchRanges` **重新遍历全文**；
   查询变化也扫全文且无上限。

## 改动
- `src-tauri/src/dirsize.rs`：`remaining_until` + `timed_out` 辅助；`start` 建立**单一 deadline**
  贯穿 `detect_flavor` + `compute`；`DuRun` 新增 `TimedOut` / `Failed`；
  `compute_du` 用**耗时 ≥ 80% 预算**或错误文本判定超时 → **不回退**；
  回退 SFTP 用剩余预算（不再重新计时）。
- `src/workbench/views/remote-file/use-dir-size-queue.ts`：新增 `dropQueued(keep?)`（只清本地
  待发送队列，**不动已提交后端的任务** —— 同会话多面板共享，贸然 cancel 会误伤）；
  卸载时清空队列；新增 `AUTO_DIR_SIZE_LIMIT = 12`。
- `RemoteFilePanel.tsx`：自动统计只为**前 12 个**文件夹排队；切换目录时 `dropQueued` 丢弃
  不在当前目录的待执行项；导出改为 `memo`。
- `TerminalView.tsx`：`closeFiles = useCallback(...)`，让 memo 真正生效。
- `src/lib/cm-search.ts`：`scanMatches`（上限 `MATCH_SCAN_LIMIT = 2000`，返回 `truncated`）；
  签名放宽为 `{ state: EditorState }` 便于测试；`matchRanges` 保留（无限额）。
- `code-search-box.tsx`：缓存已扫描区间（`rangesRef`）+ 文档快照（CodeMirror `Text` 不可变，
  引用比较 O(1)）；`keyup/mouseup` 只在文档变化时重扫，否则只 `syncIndex`；
  搜索框在输入法组合期间不扫全文，`compositionend` 补一次；计数达到上限显示 `N+`。

## 没做 / 未实测（重要，别在报告里夸大）
- **没有真实 SSH 环境**：按键→sshInput 延迟、按键→远程回显、渲染次数与耗时、目录首屏耗时、
  队列长度与取消耗时均**未实测**，只做了代码级分析与结构约束测试。
- **命令中心**（第四部分）未改：`use-command-suggestions` 已有 120ms 防抖 + 过期丢弃；
  `CommandCenterView` 的远程工具探测缓存/批处理**未动**。
- **大目录虚拟列表**未做（改动大、风险高）；当前只做了 memo + 队列限流。
- 提示框定位的 rAF 合并未做。

## 遗留风险
- `compute_du` 的超时判定依赖**耗时比例 + 错误文本**（`exec` 返回字符串错误，无结构化分类）。
  要更可靠需要给 `SshSessionManager::exec` 加结构化错误类型。
- `AUTO_DIR_SIZE_LIMIT = 12` 是经验值，未按真实目录规模调优。
