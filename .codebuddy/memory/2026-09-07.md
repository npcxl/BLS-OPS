## 终端手填参数交互修复（用户反馈：unzip 无法选择 + 提示挡输入行）

- 症状：终端输入 `unzip` 选中候选后什么都不填，只弹一条钉在**终端底部**的
  `paramHint` 警告横幅，正好盖住命令行；回车被吞成死胡同。
- 根因：`unzip <包名.zip> -d <目标目录>` 占位符无数据源（`canAutoFill=false`），
  `applyKnowledgeHit` 的 `!canAutoFill` 分支只 setParamHint + return "blocked"，
  消息里"已填入命令主体"是假的（实际什么都没填）。
- 修复：
  1. `complete.ts` 新增 `commandBody(syntax)`（第一个 `<` 前的字面前缀，
     `unzip ...` → `unzip `；主体绝不含占位符）。
  2. `TerminalView.applyKnowledgeHit`：该分支现在把命令主体填进行里（走
     `completionKeys`+`writeToShell`），draft 已以主体开头时返回 **"noop"**
     （回车→submitCurrentLine 执行，与无参候选口径一致，不再吞回车）。
  3. `paramHint` 横幅从 `bottom-1.5` 挪到 **`top-1.5`**，容器 `pointer-events-none`、
     仅"知道了"按钮 `pointer-events-auto`——不挡输入行也不挡点击/选区。
  4. `use-terminal-results.execute()`：占位符守卫通过后 `setParamHint(null)`，
     命令真正执行时清掉过期的顶部提示。
- 验证：`pnpm test` 47 文件 638 条全过（`complete.test.ts` 16 条含 commandBody
  新断言）、`pnpm build` ✅、touch `build.rs` 后 `cargo build` 重嵌 dist ✅。
- 用户偏好：浮层提示不得遮挡命令行/输入区；"不能选择"的交互宁可降级成

## dirsize 取消竞态（CI 红灯根因，已修）

- **症状**：`cancelling_a_queued_directory_size_reports_cancelled` 间歇失败
  （本地早上过/下午挂、CI 挂），报"取消后不能报 completed"。
- **两层根因**：
  1. **实现**：`cancel()` 只发 watch 信号不落状态；所有取消检查（select 前后、
     du 前后）都是 check-then-act，任务在最后检查与终态写入之间完成就能把
     `Completed` 写回去（μs 窗口）。
  2. **测试**：mock du_delay=400ms，负载高时"观察 Pending→调 cancel"的间隙
     被拉长到秒级，排队任务可能抢到名额并跑完 du——**取消晚于完成，谁也救不了**
     （ms 窗口，才是间歇失败的真正来源）。
- **修法**（`dirsize.rs`）：`DirectorySizeTask` 加 `cancelled: AtomicBool`；
  `cancel()` 顺序=立标志→发信号→**锁内落 Cancelled 终态**（排队任务立即终结）；
  `finish()`（终态唯一写入点）**在 state 锁内重读标志**，标志已置位则任何
  非取消结果改报 Cancelled；终态粘性（`update` 不覆盖终态）。取消与完成
  谁先进锁谁赢，无窗口。
- **修法**（`monitor_e2e.rs`）：该用例 du_delay 400ms→**5s**，占位扫描在
  断言窗口内不可能完成，"排队中"成为稳定状态。
- 验证：单用例 6/6、monitor_e2e 19/19、全量 420 过、fmt 干净。
- **教训**：e2e 时序断言要给"稳定状态"留出远大于调度抖动的窗口；CI 红灯
  先本地连跑 N 次复现，别信"早上还是绿的"。
