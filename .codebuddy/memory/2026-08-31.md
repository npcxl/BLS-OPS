## 第三轮：修验收阻塞项（基于 ef4c9fe 的验收报告）

### 1. ProxyJump 指纹信任目标错误（核心 bug）
- 原因：`commands.rs` 把 `host`/`port`（最终目标）和 `hop`（展示用字符串）一起返回，前端 `resolveChallenge` 用 `challenge.host/port` 存指纹 → 跳板机指纹被存到目标机名下 → 无限循环。
- 修复：新增纯函数 `ssh::evaluate_host_key(endpoint, trusted, observed) -> HostKeyVerdict`（Trusted / Unknown / Changed），`ConnectOutcome` 改为返回 `challenge_host` / `challenge_port`（真正出示密钥的端点）。`host`/`port` 只作展示。
- 前端：`SshConnectResult`、`HostKeyChallenge` 同步改为 `challenge_host/challenge_port` + `isJumpHop`；弹窗在跳板机场景明确提示"这是跳板机的指纹，不是目标服务器的"。
- **变异验证**：故意把 challenge 改回返回 target.host，测试立刻失败并报 `challenge must name the jump host's port` —— 证明测试不是摆设。

### 2. SSH 全局锁跨网络 await
- `SshSessionManager.sessions` 改为 `HashMap<String, Arc<SshSession>>`，`SshSession.writer` 用独立的 `Mutex`。
- 新增 `get()`：查表后立刻释放全局锁再返回 Arc，所有网络 I/O 都不在全局锁内进行。

### 3. 优雅断开
- 新增 `SshSession::shutdown()`：channel `eof()` → channel `close()` → `handle.disconnect(Disconnect::ByApplication, ...)`。
- `disconnect()` 先从注册表移除（防止新操作进入），再 shutdown。

### 4. 端到端测试（新增 `src-tauri/tests/ssh_e2e.rs`，10 个）
- 用 **russh server 在进程内起真实 SSH 服务端**（ed25519 主机密钥 + 127.0.0.1 随机端口），驱动生产代码同一套 `SshSessionManager`。
- 覆盖：首次连接未信任指纹、指纹变更、信任→重连→拿 shell→输入回显→Resize、密码错误、ProxyJump 逐跳信任、跳板机拒绝隧道、断开幂等、多会话互不干扰、未知会话操作报错。
- 测试服务端自身的坑：`Handler::data` 会对 direct-tcpip 隧道通道也触发，必须用 `HashSet<ChannelId>` 记录隧道通道并跳过回显，否则会往隧道里注入 "echo:" 污染内层 SSH 流（表现为 `Bad packet size: 1701013615`，即 "echo" 的 ASCII）。
- `Cargo.toml` 加 `[dev-dependencies] rand = "0.10"`；`lib.rs` 的 `mod ssh` 改为 `pub mod ssh`。

### 5. CI

### 第二步：SFTP 只读文件浏览器
- Rust：russh-sftp 2.4；SshSession 挂 `Mutex<Option<Arc<SftpSession>>>`（SftpSession 不可 Clone 但方法只要 &self）+ cwd 状态；`sftp_open/list_dir/realpath/stat(lstat)/close`；`posix_join/posix_normalize/natural_cmp` 纯函数；shutdown 先关 SFTP。
- 关键教训：russh 0.63 服务端 CHANNEL_DATA 会同时投递给 channel stream 和 Handler::data —— 测试服务端必须把 SFTP 通道排除出 data() 回显，否则 INIT 被回显污染（隧道通道同理）。
- 关键教训 2：测试服务端必须在回复 channel_success 之前调用 into_stream()，否则客户端 INIT 可能在注册前到达丢失。
