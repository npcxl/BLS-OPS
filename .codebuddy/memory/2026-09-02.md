## 两个真实 bug 修复（用户实测报错）

### 通用教训（重要）
- **凡是通过 shell 执行的命令，含 `|` `&` `;` `$` `` ` `` 的值必须整体加引号**，尤其是 `docker --format` 这种 Go template（天然带 `|` 分隔符）。`safe.rs` 的 `quoted()` 只用于插值参数，**写死在常量里的模板要自己加引号**。
- **批量命令（batched systemctl show / docker inspect）必须逐个校验并跳过坏项**，不能让一个坏参数废掉整批——否则用户看到的是"整类功能全空"，而非"少了几条"。这延续了"部分证据好过没有证据"原则。

## UI 交互 bug：模块切换后右侧内容不更新（用户实测）
- 现象：点「项目」选服务器 → 点「终端」再选同一服务器 → 右侧仍是项目内容。
- **根因 1（`workbench-store.ts` `findLeafWithServer`）**：只按 `serverId` 匹配 tab，**不区分 tab 类型**。项目 tab 和终端 tab 都带同一 serverId，终端侧边栏点服务器时复用了**项目 tab**。**修复：函数增加 `tabType` 参数，匹配 `serverId && tab.type === tabType`**。
- **根因 2（`openModuleTab`）**：对 ssh/servers 模块只 `return { activeModule: module }`，**不改 `activeTabId`**。而右侧渲染的是 `pane.activeTabId`（`WorkbenchPane`），`activeModule` 只驱动左侧栏与 rail 高亮 → 侧栏变了、内容没变。**修复：切模块时激活本模块的 tab（`TAB_TYPE_TO_MODULE[tab.type] === module`）；若没有则置 `activeTabId = null`**。
- **配套修复（`WorkbenchPane`）**：原判断 `tabs.length === 0 ? EmptyPaneState : …`，当 `activeTabId = null` 时会把所有 tab 渲染成 hidden → 右侧空白。改为 `tabs.length === 0 || !tabs.some(t => t.id === activeTabId)` 时显示 `EmptyPaneState`。
- **新增 `src/stores/workbench-store.test.ts`**（6 个用例）：覆盖模块⇄tab 路由、跨类型 tab 复用回归、同服务器 project/terminal tab 独立、activeModule 同步。前端测试 52 → 58。
- 顺带修了既存 tsc 错误 `views/project/ScanProgress.tsx` 未使用的 `cn` 导入。
- **架构要点**：`activeModule`（模块/左侧栏/rail）与 `pane.activeTabId`（右侧内容）是两个独立状态，**任何模块切换都必须同时维护两者**，否则出现"侧栏变了内容没变"。测试文件用 `findActiveLeaf` 辅助定位持有 active tab 的叶子 pane。
