# 国际化（i18n）

> 状态：**现行**，对照代码日期 2026-11-20。
> 技术栈：`i18next` + `react-i18next`（v26 / v17）。**natural keys**：key 就是英文文案本身。

---

## 1. 核心事实

- 只维护**两种语言**（2026-11-11 定稿）：`en` 与 `zh-CN`。zh-TW / ja / ko / es / fr / de / ru / pt-BR 目录已删除 —— 半翻译状态比英文原文更糟。
- **默认语言英文**：`en` 不需要翻译资源，找不到 key 时 i18next 原样返回 key，界面即英文。
- `zh-CN` 必须**全量**；缺条目由 `fallbackLng: "en"` 兜底，界面永远不出现裸 key。
- 首次启动按使用者地区推断：`navigator.language` 含 `zh*`，或时区落在大中华区 → 中文；否则英文。用户手动切换后以 `localStorage` 为准。
- 切换语言是**动态**的：`changeLocale(code)` → 持久化 → `i18next.changeLanguage` → 所有 `useTranslation()` 组件自动重渲染，无需重启。
- 语言清单唯一定义处：`src/i18n/locales.ts`（`LOCALES` / `DEFAULT_LOCALE` / `LOCALE_STORAGE_KEY` / `localeLabel`）。

---

## 2. 怎么用

```tsx
// React 组件（响应式）
import { useTranslation } from "react-i18next";
const { t } = useTranslation();
t("Connect");
t("Connected to {{host}}", { host });
t("{{count}} servers", { count: 3 });
```

```ts
// 纯 TS 模块（错误工厂、store 提示语）
import { i18n } from "@/i18n";
i18n.t("Session not found");
```

规则：

- 插值只用 `{{name}}`；**禁止字符串拼接文案**（`"已连接 " + host` 必须改成插值）。
- 模块级常量（对象/数组）里不能用 hook → 常量存英文 key，渲染处统一 `t(...)`。
- 不翻：Rust 错误消息、`catalog` 标题、远程命令输出/快照、代码注释、`console.*`、测试名。
- 要翻：JSX 可见文本、`title` / `aria-label` / `placeholder`、ConfirmDialog 的 title/description、会显示到 UI 的 Error message、下拉选项 label、空态文案、按钮文字。

## 3. 目录结构

```text
src/i18n/
├─ locales.ts              语言清单（唯一定义）
├─ index.ts                同步初始化、语言推断、chineseIdentityMap
├─ use-locale.ts           切换 hook
├─ locales/en/             natural keys 的中文 key 英文补充、数据库相关文案
│  └─ index.ts             只做 spread 合并
├─ locales/zh-CN/          全量中文，按模块分文件（common / workbench / terminal /
│                          servers / commandCenter / monitor / database / …）
│  └─ index.ts             只做 spread 合并（common 最前）
└─ test/indirect-keys.test.ts   动态 key 的机械断言
```

语言文件**按模块单独成文件**，不要都堆进一个文件（用户裁决）。新增模块文案：在 `zh-CN/` 新建或追加对应文件，在 `zh-CN/index.ts` 合并；`common.ts` 只放跨模块通用词。

---

## 4. 数据库工作台的中文 key（有意的例外）

数据库工作台早期直接写 `t("已打开")` / `t("文件格式")` 这类中文 key。现状：

- `locales/en/*` 为这些中文 key 提供英文，英文界面才不漏中文。
- `src/i18n/index.ts::chineseIdentityMap()` 把 `en` 中所有"key 本身是中文"的条目在 `zh-CN` 下补成恒等映射，避免 `fallbackLng: "en"` 让中文界面显示英文。
- 新增中文 key 必须同时进 `locales/en/`；`labels.test.ts` 会断言 zh-CN/zh-TW 下 `t(label) !== label`（专有名词若英文即译文，要写成可翻译短语或补中文）。

新代码优先用英文 natural key；不要把新的中文 key 扩散到别的模块。

---

## 5. 三禁手

1. **禁 `parseMissingKeyHandler: (key) => key`**：会覆盖插值，`{{host}}` 原样漏出（见 `index.ts` 注释）。
2. **禁 `keySeparator` / 嵌套 key**：全部是扁平字符串。
3. **通用词只进 `common.ts`**：模块文件不重复；同文件同 key 重复是 TS1117，`zh-CN/index.ts` 合并顺序 `common` 最前。

另外：i18n 是全局合并命名空间，新增裸词前先确认没被占用（`Archive` 已被"压缩包"占用、`Published` 被"发布时间"占用、`Note` 被"提示"占用）。新功能用带前缀的具体 key（`Archive knowledge` / `Knowledge published` / `Knowledge note`）。

---

## 6. 动态 key 与复查

`t("...")` 的静态扫描**必须带词边界**：

```text
(?<![A-Za-z])t\("
```

否则 `import("@/x")`、`.split(",")` 会被误判成 key。

间接 key（模块常量里的 `labelKey:`、`empty=`、`Record<枚举, string>` 值表）正则扫不到，由 `src/i18n/test/indirect-keys.test.ts` 用 `import.meta.glob(..., { query: "?raw" })` 读源码做机械断言。**禁用 `node:fs`**，否则 `pnpm build` 编译失败。

仍覆盖不到的两类，需要手工补：

- `Record<枚举, string>` 的值表；
- 函数返回的文案。

渲染类测试顶部要先 `import "@/i18n"`；测试环境语言固定为 `en`，断言写英文 key。

## 8. 红线

- 不重构无关代码、不改格式化风格、不动 Rust 文件。
- 中文注释里的 i18n 说明保持中文（项目惯例）。
- 新增 key 与 `t("...")` **逐字一致**（含标点与占位符）。
- 不新增语言目录，除非产品明确要求并愿意承担全量翻译。
