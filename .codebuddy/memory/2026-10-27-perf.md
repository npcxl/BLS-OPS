### #1 目录大小（部分）
- `DirectorySizeRegistry::prune_finished`：每会话最多保留 **300** 个**终态**任务结果，
  超出按 `calculated_at` 淘汰最旧。只淘汰终态，绝不动 pending/computing。
  目的：长时间浏览几百个目录后内存不无限增长（验收项"缓存/任务数/内存趋于稳定"）。

### #5 终端输出合并（本轮）
- **放在前端**，不碰 Rust 的 `reader.wait()`：在 `select!` 里取消 `wait()` 有丢消息风险。
- `use-terminal-session.ts`：把原来的 listener 回调体抽成 `handleOutput(output)`，
  listener 只做 `pendingOutput += payload` + `setTimeout(0)` 调度。
- 三条保证：顺序（按到达 append）、上限（≈512 KiB 立即 flush）、不拖回显
  （用 `setTimeout(0)` 而非 rAF —— 窗口最小化时 rAF 会暂停）。
- cleanup 里**先 `flushOutput()` 再 `disposed = true`**：否则"命令刚结束就关标签"会丢最后一行。
- 输入通道完全不经过这个缓冲。
- **天然背压**：前端处理慢 → Rust `reader.wait()` 阻塞 → SSH channel window 不满 →
  远端暂停发送。所以没有额外实现"消费进度回传"。
- 测试 `test/output-merge.test.ts` 3 条：分块 feed 与合并 feed 的 text/events/parts 线性序列一致；
  OSC 133 D 被拆到两个块时合并不漏进可见文本；尾部半截标记在合并后仍保持未完成状态。
