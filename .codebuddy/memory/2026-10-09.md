  绝不"尽力修复"。理由：草案会直接变成计划图，这里放过一个字段歧义，后面没有第二道
  确定性校验能兜住。

  payload 分区 = `user_description` / `server{deploy_root, supported_topologies}` /
  `project_analysis`（可为 null，明说"没有"而不是让模型误以为分析过）/ `allowed_*_refs`。
  不进提示词：API Key、SSH 凭据、证书私钥、DNS Token、`.env`、制品原文。
- **可复用的测试不变量**：`for target in FORBIDDEN_TARGETS { assert!(system.contains(target)) }`
  —— 清单新增任何一个词，提示词必须自动带上，测试会红。比断言具体某个词更抗改。
- 踩坑：`AiPrompt` 在 `proposal::ai`（不在 `ai::model`）；`TopologyKind` 在
  `proposal::model`（不在 `deployment::model`）。

## 下一步卡点（已探明，写在这里免得重走）
`analyze` 命令需要 `supported_topologies`（`validate_draft` 会拒不在清单里的拓扑），
但 `DeploymentEnvironment` **只有 `deploy_root`，没有能力快照字段**；能力数据在
`capability_profile` 表与实时 `capability_probe`。
两条都不能走：前端不能成为能力来源，AI 也不能自选拓扑。
正解 = 后端读能力画像 → 映射拓扑子集；读不到就传**空清单并明确报错**（宁可失败也不猜）。
之后再做：草案 → `PlanGraph` 构建（`build_plan_graph`，目前仓库里没有现成的图生成器）。

## P5.6 阶段九：analyze 打通（提示词 → 校验 → 计划图落库）
**关键发现（推翻了上阶段的"卡点"结论）**：
- `enabled_collectors()` 只存在于**实时探测** `capability_probe.rs`，数据库里**没有能力表**。
- 所以 `supported_topologies` 的语义改成「**本产品形态支持**的拓扑全集」，不是"这台机器装了什么"。
  给全集让 AI 表达**意图**；真实能力由 `session::confirm` 的预检门禁在服务器上核实并阻断。
  **理由**：宁可让预检失败，也不能让 AI 猜机器状态。
- 不写 PlanGraph 生成器：复用 P5.3 已有的 `proposal::workflow::build`（含 `params_json` 约定、
  节点风险、审批标记）。新写一套会和它打架。
- 镜像登记（`RuntimeCatalog.service_images`）**至今没有存储来源**，所以 analyze 走 workflow 路径
  而不是 `compile_services`；制品是否存在留给 preflight 核实。

**新增**：`planner/graph.rs`（草案 → 工作流输入的**写死映射表**，7 测）、
`commands::deployment_session_analyze`、前端 `deploymentSessionAnalyze` + 向导"开始分析"。

**API 名称踩坑（省得再查）**：
- 草案里的阻塞问题字段是 `blocking_questions`（不是 `questions`）
- 事件类型是 `SessionEventKind::DraftGenerated`（不是 `DraftReady`）
- `DeploymentPlan` 在 `deployment::model`（不是 `proposal::model`）
- `DraftRejection` **刻意没有** `Serialize` → 用 `Debug` 拼接
- `db::deployment_session` **没有** `set_question`；直接改 `session.current_question` + `upsert_session`
- 状态机**不允许** `created → analyzing`，必须 `created → importing → analyzing`

**映射规则里刻意不猜的地方**：`self_hosted_database` 只从 `dependency_decisions`
（`kind == "database"` 且 `external == false`）推断，**不靠服务名猜**（db/mysql/pg 写法太多）。
判断不了就不加迁移节点 —— 少一个节点安全，漏一个迁移会由 preflight 报出来。

## 隐藏「部署」「任务」入口 + 私钥文件导入
- **隐藏**：`NavigationRail.tsx` 加 `HIDDEN_MODULES = new Set(["deploy","tasks"])`，只过滤导航项；
  类型 / store / 视图 / 后端命令全部保留，恢复时从集合删掉 id 即可。
  新增 `test/navigation-rail.test.ts`（3 条：不含这两项、其余一个不少、不留空分隔线）。
- **私钥文件导入**：新命令 `credential_read_private_key_file`（`commands/credentials.rs`，
  ≤64 KiB / 必须 UTF-8 / **内容必须真的像私钥**）。
  **关键决策：不用扩展名白名单** —— 最常见的 `id_rsa` / `id_ed25519` **没有扩展名**，
  按扩展名过滤会把最该支持的场景挡掉；内容是主防线。前端 dialog 也**不传 filters**。
- **OpenSSH 私钥的加密状态无法从文本判断**（信息在 base64 二进制 blob 里）→
  `encrypted: Option<bool>` 用 `None` 表示"不知道"，让 `decode_secret_key` 去判口令对错。
  踩过的坑：OpenSSH 头也匹配 `-----BEGIN ... PRIVATE KEY-----`，判断顺序必须先摘出 OpenSSH，
  否则会误报"未加密"（测试抓到过）。
- 前端：凭据表单私钥类型下加「从文件导入」，读到的内容只进表单、**用户点保存才进钥匙串**。
- 验证：后端 **690 全过**（+7）、前端 **848 全过**（+7）、`tsc --noEmit` ✓。
