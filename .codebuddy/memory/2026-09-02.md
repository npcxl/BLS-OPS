## P3 重构：部署实例优先发现（用户给完整方案后实施）
- 用户确认 P3 项目发现的主流程改为「部署实例优先」：先能力识别 → 按能力启用收集器枚举**真实部署实例**（docker ps + 逐容器 inspect 提取 Compose labels/Mounts/端口；systemctl list-units + 批量 show 提取 WorkingDirectory/ExecStart；nginx -T 提取 root/proxy_pass 并用 ss→/proc/PID/cwd 反查代理后端）→ 对实例给出的候选路径**定向 marker 扫描**（第一轮），再对 /home /srv /opt /var/www /data 做 marker-only 补充扫描（第二轮）。旧的 `ProjectInventory`（find 全量枚举 2 万个文件）与 `ProjectRuntimeInventory` 已删除。
- 新模块 `src-tauri/src/deployment_collector.rs`：`DeploymentInstance { id/kind/name/status/ports/working_directories/config_files/source_paths/source_known/detail }` + 三个收集器 + 纯解析函数（parse_systemd_show/parse_nginx_effective/parse_ss_listen/docker_instance_from_inspect）带单元测试。铁律：没有宿主线索的实例 `source_known=false`（"源码未知"），绝不伪造路径；实例输出里的路径必须过 `safe::validate_abs_path`。
- safe.rs 新 Capability：`ProjectMarkerScan`（固定根第二轮）、`ProjectDirMarkers{paths}`（定向，`validate_remote_paths` 校验 ≤64 条）、`SystemdShowUnits{units}`（≤40/批）、`DockerInspectMany{containers}`（≤20/批）、`NginxEffectiveConfig`、`ListenSockets`、`ProcCwd{pid}`；共用 `PROJECT_MARKER_PREDICATE`（marker 文件 + .git/src/app 目录，不再枚举普通文件）。
