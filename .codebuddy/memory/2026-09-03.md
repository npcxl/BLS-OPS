## 目录大小"接口正常但不渲染"根因确诊与修复（序列化契约断裂）
- **根因（确诊）**：`dirsize.rs` 的 `DirectorySizeResult` 派生 `Serialize` 但**没有** `#[serde(rename_all = "camelCase")]`，命令返回值与 `directory-size-update` 事件都发 snake_case（`session_id`/`size_bytes`/`calculated_at`），前端类型却是 camelCase → `apply()` 用 `result.sessionId`(undefined) 拼 key → 结果全部落进 `undefined::路径`，`FileRow` 用真实 `sessionId::路径` 查询永远落空 → 永远"排队中/文件夹"。接口"返回正常"但进不了正确的 key。
- 次因：① `ensureListening` 先置位 `listening=true` 再 await `listen()`（并发调用者误以为就绪、失败后永不重试）；② 面板不等监听器注册完成就 `directory_size_start`，小目录 completed 事件在注册前发出即丢失；③ 事件丢失后无兜底。
- **修复**：Rust 加 `rename_all="camelCase"`（`DirectorySizeStatus` 枚举值保持 snake_case，`is_terminal()` 统一终态判定）；store 重写（`normalizeRemotePath`+唯一 `keyOf`、apply 校验非法载荷、`calculatedAt` 防回退+终态不可被过渡态回滚、`ensureListening` 共享 Promise 失败可重试）；`useDirSizeQueue` 返回 `listenerReady`（注册成功才 true），panel 的自动计算 effect 以 `connected && listenerReady` 门控；新增 `directory_size_status_many` 命令（≤20 条去重、拒绝空路径、纯只读）+ `useDirSizeWatchdog`（每面板一个 3s 定时器、只查已启动未完成目录、全完成不发请求）。
- 测试：Rust 新增序列化契约/终态/status_many 上限去重/双会话隔离（lib 263 全过 + monitor_e2e 19）；前端新增 `dir-size-store.test.ts`、`file-row.test.tsx`（act 包裹 store 更新！）、`dir-size-queue.test.tsx`（fake timers 测 watchdog；harness 复刻 panel effect；`vi.resetModules()` 隔离模块级 listenerPromise）——vitest 128 全过。pnpm build ✓。
