## 自动更新失败 "The update could not be completed."（根因：latest.json 的 API 资产 URL）

- 现象：应用内更新到 0.1.3 失败，UI 显示 unknown 兜底文案。
- 排查：unknown = classifyUpdateError 没匹配任何规则。拉线上
  `releases/latest/download/latest.json` 发现 manifest 本身可读（check 成功），
  但 **platforms[].url 是 `api.github.com/repos/.../releases/assets/<id>`**——
  该端点匿名客户端拿到的是 401/元数据 JSON，不是安装包二进制 → 下载安装包
  阶段必失败。这是 tauri-action 生成 manifest 的已知行为。
- 修复：
  1. `scripts/rewrite-updater-urls.mjs`（新）：把 assets/<id> URL 重写为
     `github.com/<repo>/releases/download/<tag>/<encodeURIComponent(name)>`；
     资产 id→文件名映射由 `ASSET_MAP` 环境变量传入（workflow 里 gh api --jq
     `'map({(.id|tostring): .name}) | add'` 生成）；剥离 BOM；无重写时 exit 1。
  2. `release.yml`：tauri-action 后加 step——gh release download latest.json →
     node 重写 → `gh release upload --clobber` 回传；并把"Create the tag
     without bumping"两步 git 加 `|| echo` 容错（重跑已存在 tag 不再失败）。
- workflow 步骤两个 bug（已修）：`gh release download` 缺 `--clobber`（构建目录
  已有 latest.json → exit 1）；`ASSET_MAP` 的 jq 写错——`releases/tags/$TAG`
  返回**单个对象**，资产在 `.assets` → 正确写法
  `--jq '.assets | map({(.id|tostring): .name}) | add'`。
- **release 步骤第二轮 bug（404）**：tauri-action 建的是 **draft release**，
  `gh release download <tag>` 取不到 draft → 404。已改全走 API：
  `gh api repos/$R/releases/tags/$TAG` 轮询 12×5s（draft 刚建有延迟）→
  `jq '.assets | map({(.id|tostring): .name}) | add'` →
  `gh api .../releases/assets/<id> -H "Accept: application/octet-stream"` 下载
  （绕开 gh release download 的 draft 差异）→ `gh release upload --clobber`；
  失败时打印可见 release 列表与资产清单。
- **draft 与 latest.json（易踩）**：`/releases/latest/download/latest.json`
  **只认已 Publish 的 release**（GitHub latest 忽略 draft），且 draft 资产匿名
  不可下载 → 修完 manifest 必须 Publish 用户才看得到。
- 现状（2026-09-08）：tag v0.1.4、v0.1.5 已建且有 **draft release**，但它们的
  latest.json 是未重写的 API URL（当时步骤 404 失败）；published 的仍是 v0.1.3
  且它的 latest.json 也是坏的。仓库里的 `fixed-latest.json` 用完要删，别提交。
- **本机没装 gh CLI**（下面这段 gh 命令不可用）→ 改用 API/直链：
  `api.github.com/repos/.../releases/tags/<tag>`（匿名 60 次/小时，会限流）或
  `github.com/.../releases/download/<tag>/latest.json`（web_fetch 会 302 到
  release-assets，需跟重定向）。
- v0.1.3 实际资产名是**点号**形式：`Ops.Workbench_0.1.3_x64-setup.exe` /
  `_x64_en-US.msi`（label 里有空格，name 没有，URL 用 name）。
- 已本地生成修正版 `fixed-latest.json`（3 个 URL → releases/download 直链，
  signature 原样保留），验证 `4D-5A`(MZ)/200/6821334 bytes ✓。上传方式：
  GitHub release 页面删掉旧 latest.json → 把 fixed-latest.json 改名为
  latest.json 上传；或重跑 release.yml（tag=v0.1.3）自动完成。
  ```powershell
  gh release download v0.1.3 -p latest.json --output latest.json --clobber
  $env:TAG="v0.1.3"; $env:GITHUB_REPOSITORY="npcxl/BLS-OPS"
  $env:ASSET_MAP = gh api "repos/npcxl/BLS-OPS/releases/tags/v0.1.3" --jq 'map({(.id|tostring): .name}) | add'
  node scripts/rewrite-updater-urls.mjs latest.json
  gh release upload v0.1.3 latest.json --clobber
  ```
  或重跑 release.yml（workflow_dispatch + tag=v0.1.3，全量重建 ~15 分钟）。
- 教训：**tauri-action 的 latest.json URL 必须 post-process 成直链**，否则
  updater 下载必挂且报 unknown；诊断 unknown 类更新错误先看
  `[updater] check/install failed (unknown)` 后面的 detail（console）。
- 本地测脚本时 PowerShell 5.1 `Out-File -Encoding utf8` 带 BOM 会让
  JSON.parse 炸——脚本已兼容 BOM。

## 文件预览 Modal 无滚动条（h-full 百分比链 → 全链 flex 传导）

- 根因：`FilePreviewModal` ready 容器（flex-col）与各 preview 根之间用
  **`h-full`（height:100%）衔接**——百分比解析依赖包含块高度 definite，
  flex 嵌套链上任何一层解析失败，该层就被内容撑开 → 超出被
  `overflow-hidden` 的 modal 裁掉 → 内容不可达且无处滚动。
- 修复（`src/workbench/views/preview/`）：**preview 根一律 `min-h-0 flex-1`
  （flex 传导），弃用 `h-full`**——TextPreview/SheetPreview/HexPreview/
  ArchivePreview/ImagePreview/PdfPreview/MediaPreview（`flex min-h-0 flex-1
  flex-col`）、DocxPreview（`min-h-0 flex-1 overflow-auto`）、SlidesPreview
  （`flex min-h-0 flex-1`）；modal ready 容器加 `overflow-hidden` 兜底。
- 与既有教训同族："浮层限高用 calc(vh)"、"高度三件套全走 style"——
  **嵌套 flex 里 height 百分比是脆弱的，全链 flex+min-h-0 才稳**。
- pnpm build ✓（preview 无独立测试文件）。

## 补全交互统一状态机大改版（用户裁决，终端 + 命令中心同一套）

- **原则：默认只有行内 ghost，面板只在 Tab / ArrowDown 后出现**。适用于全部
  补全类型（命令/Docker/Nginx/参数/cd 目录/容器名/服务名）。
- 状态机（`terminal-suggest.ts::resolveTerminalCompleteKey`，纯函数）：
  - collapsed：Tab/↓ = `accept-first`（填 hits[0]/items[0] + 展开）；Enter =
    `run-first`（直接执行第一条，参数/风险流程照走）；无候选全部穿透。
  - expanded：↑↓ 移动、Enter = `run-active`（执行当前项）、Tab/→ =
    `accept-active`（填入当前项，filled 保持展开→多级目录连续补全）。
  - 任何状态 Esc = `clear-line`（远程 Ctrl+U + 本地 LineEditor 清 + 关面板）。
  - 展开后**任何非程序性 draft 变化 → 回 collapsed**。
- 终端接线（TerminalView）：
  - `dismissedDraft` 机制**退役**（Enter 从"填入"改"执行"，无第二次 Enter 问题）；
    换成 `programmaticDraftRef`：程序性写行（applySuggestion/paramPicker/手填
    主体）标记 draft，draft effect 比对——相同=程序性，保持 expanded；
    不同=用户编辑，回 collapsed。**填入后必须先设 ref 再 setDraft**。
  - `suggestionsEnabled` 去掉 dismissedDraft 条件（空输入门控已有）。
  - 面板渲染条件 `suggestExpanded && !paramPicker`；ghost 渲染条件
    `!expanded && !paramPicker && ghostText!==""`。
  - `terminal-ghost.tsx`（新）：`pointer-events-none` 光标锚点灰色文本 + Tab
    徽标，字体/行高取 xterm options。**不是面板**——不挡点击/复制。
  - `ghostTextFor(item, line, parsedPrefix)`：token 类 insertText 减 parsedPrefix
    （`cd o`→`ps/`）；全语法类减整行（`docker p`→`s -a`）；都不匹配（裸 cd
    `" fd/"`）→ 整条显示（**ghost 自带前导空格**）；空输入/无候选 → ""。
  - ArrowUp 在 collapsed 穿透（shell 历史）。
- 命令中心（CommandCenterView）：
  - 删 "x hits" 命中数；collapsed Enter 固定执行 `hits[0]`（expanded 改字后
    activeIndex 可能残留，绝不能用它）；ArrowDown collapsed = 填入+展开；
    onChange 里 `expanded && setExpanded(false)`。
- 终端 cd 补全：
  - Provider `matches` 接管 `index===0`（裸 cd）+ `index===1`；bareCd 判据 =
    index 0 && tokens.length===1 && cursor>=token.end；**不能用 parsed.prefix
    （是 "cd"）**，按空参解析；insertText 前加空格、replaceRange 从 cursor 起。
  - `remote-cwd.ts` 加 `uncertain`：cd 提交后 exitCode===null（无 OSC 133 D
    也无 OSC 7）→ path 保留旧值但 uncertain=true；`needsProbe` 纳入 uncertain；
    cd 失败（exitCode!==0）是**确定态不标 uncertain**；OSC 7 / 成功 cd /
    probe 都清 uncertain。

  remote-directory 27 条（裸 cd 5 条）；`remote-cwd.test.ts` +5（uncertain）；
